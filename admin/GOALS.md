# Текущая цель проекта (читать перед началом работы)

Делаем админку, в которую **автоматически** попадают все поля по объектам
с портала ShaffofQurilish/dshk (GASN-объекты, `cam_id` вида `GASN-<object_id>`).

Раньше часть объектов заносилась вручную через Excel-мастер
(`source_sheet != 'gasn'`). **Задача — максимально заменить мастер
автоматикой**: всё, что можно получить с портала (shaffof + nazorat.mc.uz
object-info + PDF выписки), должно подтягиваться само, без ручного ввода
человеком.

## Что уже автоматизировано
- `import_shaffof.py` — массовый импорт списка объектов с shaffofqurilish
  (`list-construction` bulk API) в `complexes` (cam_id, адрес, статус,
  координаты, дедлайн и т.д.).
- `object_info_parser.py` + route `/complex/<cam_id>/delay/fetch-portal` —
  по кнопке в карточке (только для GASN-объектов) подтягивает с
  `nazorat.mc.uz/object-info/{object_id}`:
  - permit_date (дата выдачи разрешения),
  - portal_deadline (дедлайн по версии портала),
  - expertise_number, apz_number,
  и автоматически скачивает PDF-выписку (ariza/ko'chirma) через
  `api-nazorat.mc.uz/api/get-object-pdf/{object_id}` — парсит её через
  `ariza_parser.py` (application_number, smr_registration_date, doc_hash,
  applicant_name, tax_id) без ручной загрузки файла.
- `ariza_parser.py` — парсинг PDF выписки вручную загруженной (fallback,
  если автоскачивание не нашло PDF на портале).

## Что НЕ автоматизировано / не входит в scope
- Документы экспертизы и АПЗ (xulosa) — табличная верстка PDF, парсинг
  ненадёжный (путает label/value), решили не делать сейчас.
- Объекты из старого Excel-мастера (не GASN) — у них нет object_id для
  портала, для них автоматизации с nazorat.mc.uz быть не может в принципе;
  их нужно по возможности замещать/сверять с GASN-данными, а не наоборот.
