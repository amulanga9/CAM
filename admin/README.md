# CAM admin (v1)

Простая админка для проверки устаревших/неясных статусов ЖК между циклами
парсинга и обучения модели.

## Установка

```
pip install -r requirements.txt
```

## Workflow

1. Положить новый мастер-Excel в `data/cam_master_2026_06_new.xlsx`
   (или поменять путь в `import_master.py`).
2. `python3 import_master.py` — пересобирает `cam_admin.db` из Excel.
   Объекты с неоднозначным `case_status` (грязный текст вместо чистого
   статуса Shaffof) или просроченные "Jarayonda" автоматически попадают
   в очередь проверки. Ранее сохранённые ручные решения (`cam_manual.db`)
   автоматически переприменяются поверх пересобранных данных.
3. `python3 app.py` — запустить админку на http://127.0.0.1:5000
   - `/review` — очередь объектов, ожидающих подтверждения
     (Сдан / Строится / Заморожен / Отменён), с кнопкой "Не ЖК — убрать из базы"
   - `/all` — поиск и фильтр по всем объектам
   - `/complex/<cam_id>` — детальная карточка: все поля доступны для
     дозаполнения/исправления, ссылка на коммерческую продажу
     (domtut/imo.uz/др.), история проверок, все исходные поля
   - `/new` — добавить объект без CAM ID (требуется адрес), получает
     временный id вида `MAN-0001`
4. `python3 export_training.py` — выгружает текущее состояние (с учётом
   ручных решений) в `data/cam_training_export.csv` для следующего
   обучения модели.

## Структура БД: два файла

Данные разделены на два физических SQLite-файла, чтобы пересборка из
Excel никогда не уничтожала ручную работу:

- **`cam_admin.db`** — "слепок" из Excel. Полностью пересобирается с нуля
  каждым запуском `import_master.py`. Можно свободно удалять.
  - `complexes` — все объекты (объединены все "объектные" листы исходного
    Excel), полная исходная строка сохранена в `raw_json`
  - `developers` / `contractors` — справочники из листов "Все застройщики"/"Все подрядчики"

- **`cam_manual.db`** — ⚠️ **НИКОГДА не удалять.** Здесь живёт вся ручная
  работа: подтверждённые статусы, исключённые "не ЖК" объекты, правки
  полей, вручную добавленные объекты без CAM ID. Этот файл не
  пересоздаётся `import_master.py` (только `CREATE TABLE IF NOT EXISTS`)
  и не попадает в git (см. `.gitignore`) — делай резервную копию сам.
  - `reviews` — журнал ручных решений (cam_id, дата, вердикт, комментарий)
  - `excluded_ids` — объекты, помеченные как "не ЖК"; больше не
    возвращаются при реимпорте из Excel
  - `overrides` — ручные правки полей карточки, переживают реимпорт
  - `manual_complexes` — объекты, добавленные через `/new` без CAM ID

Оба файла подключаются в одном соединении через `ATTACH DATABASE`
(алиас `manual`), поэтому из кода можно одним запросом джойнить
`complexes` с `manual.reviews` и т.д.
